summary `FROZEN` or `READY_FOR_PAYROLL`, or a `PayrollRun` for the
company-month `APPROVED / LOCKED / POSTED`. `checkMonthNotFrozen` and the new
`checkRangeNotFrozen` (every month of a range) wrap it.

- Applied to every writer that skipped it: OT approve (manager stage) and
  OT reject / bulk-reject, LOM reject / bulk-approve / bulk-reject,
  permission HR approve, comp-off approve, shift override writers
  (bulk-shift-upload, shift-plan, shift-change approve), and every ESS
  submit route (mispunch, OT request, on-duty, WFH, permission, comp-off,
  leave × 2).
- `refreshMonthlySummary` refuses a locked month; reopen refuses while
  payroll is processed and refreshes only the employees it reopened (and can
  now reopen `READY_FOR_PAYROLL`); finalize refuses locked months; **payroll
  lock freezes the month's summaries** in the same transaction.

**Sync does not undo decisions** — `biometricSync.ts`,
`biometricConversion.ts`, `attendanceHistory.ts`:

- Rows a person wrote (`source = manual`) and Leave / On-Duty days are
  skipped by device data (`isProtectedFromDeviceOverwrite`), counted as
  `skippedProtected`.
- OT is re-queued only when calculated minutes change; LOM only when
  late/early-out minutes change — an unchanged re-sync keeps the approval.
- Sync now honours shift overrides, writes early-out, and sets
  weekly-off / holiday-worked flags like the import path.

**Mispunch** — `mispunch/[id]/approve` merges the requested time with the
recorded punch (one-sided request no longer becomes Absent), uses the
override-aware shift, writes early-out and WO/holiday flags, checks company

## 2. Biometric Device Sync — diagnosed and fixed

- Root-caused "fetch failed" as a real network problem, not an app bug: the device controller's address kept changing (`192.168.1.162:8080` → briefly unreachable → tried `192.168.1.151:8070` (typo'd IP, then wrong port) → `192.168.1.151:9593` (turned out to be an unrelated JBoss server, not the biometric API) → confirmed the correct, working address is the original **`192.168.1.162:8080`**, back online.

## 3. Real bug fix — Designations & Grades / Departments / Sub Departments were 500ing

- Root cause: `src/lib/master-headcount.ts` was filtering `{ not: null }` on `JobInfo.departmentId` / `designationId` — both are **required** (non-nullable) columns, and Prisma rejects a not-null filter on an already-required Int field. Only `subDepartmentId` is actually nullable and needed that filter.
- Fixed by only applying the exclusion where the field is genuinely nullable. This unblocked the Designations tab, the Grade form's designation dropdown, Departments, and Sub Departments — all of which depend on the same headcount helper.
- Separately found and fixed the same class of drift again later in the day: migrations 000025–000030 ("masters review batch," `budget`/`experienceYears`/`qualification`/`reportsToId` on Designation, plus new `GrossSplitRule`/`Site`/`DeductionRate` tables) existed in `schema.prisma` but had **never fully landed in the database** — one all-or-nothing migration transaction had rolled back silently on a duplicate column, and four other migrations had created their tables but **none of their foreign-key constraints**. Wrote a gap-fill migration (`000034_masters_review_batch1_gapfill`) adding exactly the missing pieces (2 columns + `reportsToId` + 5 FK constraints + 2 indexes), verified column-by-column against the live DB before and after.

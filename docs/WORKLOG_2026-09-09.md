## 3. Biometric "not fetching" — root cause

- Local showed "Device API is not configured": `BIOMETRIC_API_URL` / `BIOMETRIC_API_KEY` were missing from local `.env` (they exist only on the live stack). User supplied both; added to `.env` (gitignored). Scheduler now starts locally.
- The failed rows on both live and local are `error: "fetch failed"` — a network-level failure. From this PC (192.168.2.130): `192.168.1.162` answers ping and traceroute (2 hops via the router), but **TCP 8080 is refused/timed out**; only 135/445/3389 are open on that box. The shared SQL Server on the same subnet is reachable, so it isn't routing. No system proxy configured; failure reproduces in curl, PowerShell, Node, and outside the tool sandbox.
- The JSON the user downloaded at 16:02 (from this PC) proves the service *was* answering minutes before the port was refused → the controller service on `.162` is flapping and/or its Windows Firewall rule is scoped to the local subnet. **Fix is on the `.162` machine** (start/auto-start the service listening on `0.0.0.0:8080`; open inbound 8080 for 192.168.2.0/24 and the live server's subnet). Nothing in HRMS needs changing; syncs will succeed on the next tick once 8080 answers.

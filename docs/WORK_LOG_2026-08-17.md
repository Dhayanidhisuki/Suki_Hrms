## 15. Email Gap Analysis (Session 2 — 18:00 IST)

Performed a full audit of the calibration email integration and identified 7 gaps explaining why emails were not being delivered automatically.

### Critical gaps identified:
1. **No scheduler** — `/api/cron/calibration-notifications` is an HTTP endpoint; nothing external calls it. Email never fires automatically.
2. **`CRON_SECRET` missing** — `.env` has SMTP config but no `CRON_SECRET`. Every call to the cron endpoint returns 401 Unauthorized.
3. **`RECEIVE_EMAIL` not seeded to roles in DB** — Migration `20260817170000` was prepared but the three operational roles (Calibration Engineer, Quality Engineer, Quality Manager) did not yet have RECEIVE_EMAIL rows in the live database. `findNotificationUsers()` returns 0 users → 0 emails sent.
4. **Users missing email addresses** — `findNotificationUsers()` filters `email: { not: null }`; users without email are silently excluded.
5. **Users missing unit scope** — Tools without a matching unit scope are invisible to users with no scope assigned.
6. **`emailEnabled` toggle may be off** — The function exits early with 0 deliveries if this DB flag is false.
7. **SMTP password exposed in `.env`** — Credentials should be rotated.

### Deliverable: Full gap analysis document created at `email_gap_analysis.md`.

## 17. Force-Resend Fix — "Already Sent Without Email" (Session 2 — 18:13 IST)

**Problem:** After adding email addresses to users, the system reported "already sent" and skipped delivery. The deduplication guard (`existing?.status === "SENT"`) prevented re-delivery to users whose email was added after the milestone window had already been logged.

### Changes:

#### `src/lib/calibrationDueEmail.ts`
- Added `options: { force?: boolean }` parameter to `runCalibrationDueEmails`.
- When `force: true`, the SENT check is skipped — all eligible users receive their digest regardless of prior delivery history.
- Return payload now includes `forced: boolean` for UI display.

#### `src/app/api/cron/calibration-notifications/route.ts`
- **GET** — unchanged, CRON_SECRET authentication for scheduled runs.
- **POST** — new handler, session + `canManageSettings` permission (no CRON_SECRET required from browser). Calls `runCalibrationDueEmails` with `force: true`. Also accepts `{ testEmail }` body for branded test sends from the UI.

#### `src/app/dashboard/settings/notifications/email/page.tsx` — full rebuild
- **📤 Resend Digest Now** button in page header — calls POST, ignores SENT history.
- **Send Test Email** inline form — test to any address without leaving the settings page.
- **Result banner** — live feedback: sent / skipped / failed count or test delivery status.
- **Ready count** — green circle showing how many users are fully eligible.

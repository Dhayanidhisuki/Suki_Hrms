# Worklog — 31 Jul 2026

## Summary
Deep-verified the tools lifecycle data model against live `ERPDb_Manpro` (and all
sibling DBs on the server), then rebuilt three modules on confirmed columns only:
**Tools Manage list/detail** (GAUGE_SERIAL_NO-driven status roll-up, spec'd list
columns, machine link), **Tool Subgroup master** (confirmed QMS_OTHER_TOOLS_TYPE
fields, Asset Category dropped as placeholder-only data), and fixed the
**Reorder Level** screen that always showed "No records found" due to a
fetch-then-filter bug. Also fixed latent non-identity `ROW_ID` create bugs
surfaced by Prisma client regeneration.

## Details

### 1. Data-model verification (live ERPDb_Manpro)
- `GAUGEANDTOOLS.STATUS` holds only `NULL` / `'Available'` — no CREATED/APPROVED
  lifecycle exists anywhere in the tools/gauge schema (checked every
  `%STATUS%` column across all 29 TOOL/GAUGE tables + approval-like columns
  across the whole DB).
- Real per-unit state machine confirmed on `GAUGE_SERIAL_NO.STATUS`:
  NEW PURCHASE → INHOUSE/VENDOR USE → ISSUE FOR CALIBRATION →
  AVAILABLE FOR USE / REJECTED / WORN OUT (1,504 unit rows).
- `GAUGE_CONTROL_CARD(_TRANS)` is **empty in every database on the server**;
  no FK, join key unverifiable. Live calibration history actually lives in
  `TOOLS_TRANS_ISSUE_FOR_CALIBRATION` — 145/145 rows match a unit on
  `(TOOL_OR_GAUGE_NO, SERIAL_NO)`, carries cali + preventive dates.
- Per-unit issue linkage is broken in real data: `TOOLS_TRANS_ISSUE` has
  `TOOL_REF_NO=0` / `SERIAL_NO=1` on ~all lines (2 of 51,916 match a unit);
  `REC_STATUS` almost never updated (19 'Received' vs 52k 'Pending').
  → "Issue To / DC" resolved at tool level; exact per-unit only for calibration.
- `GAUGE_SERIAL_NO` linkage by `TOOL_OR_GAUGE_NO` ≡ by `TOOL_REF_NO`
  (0 mismatches), so the existing Prisma relation is safe for filtering.

### 2. Tools Manage — list + detail on the confirmed model
- New `src/lib/toolStatusRollup.ts`: badge computation + matching Prisma
  `where` fragments (single source, so row badge and DB filtering agree).
  Priority: In Calibration → Needs Attention → Available → **In Use** (new
  tier for INHOUSE/VENDOR USE/NEW PURCHASE) → Inactive → No Units.
- **Verified partition:** all 13,797 tools map to exactly one badge
  (137 / 4 / 1,264 / 31 / 238 / 12,123); the In Use tier recovers 31 tools
  that would have shown a false "No Units".
- `GET /api/tools`: returns `computedStatus` + `machines`
  (`TOOLS_MACHINE_TRANS` codes); status filter now DB-side on the roll-up;
  `GAUGEANDTOOLS.STATUS` no longer used anywhere in list/detail views.
- List page: spec'd columns (Tool Or Gauge No, Description, Total Qty,
  Avail.For.Iss., Location, Ret?, Sl.No?, Issue Type, Critical?, PS.Min/Max,
  Ref. No, Least Count, Buffer Qty) + roll-up Status badge + Machine icon
  (link when mapped, disabled otherwise). KPIs/filter switched to roll-up.
- Mapped `LEAST_COUNT` on the Prisma model. Note: PS.Min uses real column
  `PROD_SPEC_LOWER_MAX` (`PROD_SPEC_LOWER_MIN` does not exist).
- Detail page unit table already sourced from
  `TOOLS_TRANS_ISSUE_FOR_CALIBRATION`; removed remaining
  `GAUGEANDTOOLS.STATUS` fallbacks; "No records found" kept for
  zero-unit tools (legacy behavior).

### 3. Tool Subgroup master — rebuilt on QMS_OTHER_TOOLS_TYPE
- Verified before build: `PREFIX_BASED` real values = 'Group' (54) +
  one saved '-Select-' placeholder → field built as **free text** (decision);
  join `REF_GROUP_ID → OTHER_TOOLS_TYPE.ROW_ID` (PK), display name from
  `OTHER_TYPE`; 75/75 subgroups resolve to a parent.
- **Asset Category removed everywhere** (only value ever stored is the
  '-Select-' placeholder — no data-driven option list exists). No separate
  "Subgroup Code" field (not a stored column; `SUB-n` stays display-only,
  ROW_ID-derived — matches legacy "SUB-73" = LEAD GAUGE).
- Form = exactly the confirmed fields: Subgroup Name*, Parent Group*
  (dropdown from OTHER_TOOLS_TYPE), Prefix Tools No, Is Auto Generate Code?
  (Yes/No; stored literally), Prefix Based. List: Name, Parent Group,
  Prefix Tools No, Created By, Created Date. Audit fields display-only
  in the detail modal.
- API: POST validates via schema, computes `ROW_ID` max+1
  (**not identity in ERP** — old create would fail at runtime), '-Select-'
  normalized to NULL on read; PUT stamps `LST_UPDT_USER_ID_CD`/`LST_UPDT_TS`
  (added to Prisma model); legacy `code` alias kept for the Lookups screen.

### 4. Reorder Level — empty table bug
- **Cause:** API took the first 500 tools *alphabetically* then filtered for
  ROL in JS. Only 3 of 13,797 tools have `MIN_ORDER_LEVEL > 0`, first at
  alphabetical position ~1,349 → always empty.
- **Fix:** filter in DB (`minOrderLevel > 0`); Status column now derived
  ("Below ROL"/"OK") instead of the signal-less `GAUGEANDTOOLS.STATUS`.
- **Verified:** 3 rows returned (MP-TRG-501 GO, OTH_C01243, OTH_C01245 —
  all qtyIn 0 ≤ ROL 1). Page remains a `SimpleMasterShell` stub (no KPIs/
  search) — upgrade optional.

## Key decisions
1. Calibration history source = `TOOLS_TRANS_ISSUE_FOR_CALIBRATION`
   (verified), not the empty/unverifiable `GAUGE_CONTROL_CARD_TRANS`.
2. Status badge priority confirmed + "In Use" tier added (below Available,
   above Inactive).
3. Issue To/DC resolved tool-level (per-unit linkage unsupported by data);
   exact per-unit join only for calibration issues.
4. `PREFIX_BASED` = free text until the legacy screen owner confirms the
   dropdown option list.
5. Legacy '-Select-' placeholders treated as NULL on read; never written.
